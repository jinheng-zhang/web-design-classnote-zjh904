认识 Swiper是什么 · 谁在用 · 怎么装

Swiper 是一款免费开源的纯 JavaScript 轮播组件库，支持鼠标拖动、触摸滑动、自动播放，手机和电脑通吃——所以它几乎出现在每一个需要"翻页"的网站上。

它不是框架，只是一个 CSS 文件 + 一个 JS 文件，通过 CDN 两行代码即可引入（就像从图书馆借两本书，不用自己写）：

<!-- 第 1 行：官方样式表 -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/swiper@11/swiper-bundle.min.css">
<!-- 第 2 行：官方脚本 -->
<script src="https://cdn.jsdelivr.net/npm/swiper@11/swiper-bundle.min.js"></script>

▎提示词（向 AI 请教未讲过的 API）我要给 Swiper 轮播加一个课堂没讲的第 7 种效果 creative（自定义变换）。请打开官方示例 swiper/demo/257-effect-creative.html，读懂 creativeEffect，回答我三件事： 1. creativeEffect 里 prev 和 next 各自能写哪些参数？分别控制什么？ 2. translate 数组的三个值 [x, y, z] 单位分别是什么？百分比是相对哪个元素算的？ 3. 怎样实现"上一张缩小左移并带角度、下一张放大右移进场"这种电影墙效果？给我一段可直接用的配置。
AI 回答要点（我随后对照本地 swiper/types/modules/effect-creative.d.ts 逐条核实）： prev / next 各支持 6 个可选参数： translate（[x, y, z] 位移）、rotate（[x, y, z] 角度，单位 deg）、opacity（透明度）、 scale（缩放）、shadow（投影）、origin（变换原点）； 顶层还有 limitProgress、shadowPerProgress、progressMultiplier、perspective。
translate 的 x/y 写字符串就是百分比、写数字就是 px，z 只能是 px； 官方示例里 prev: { translate: ['-20%', 0, -1] }、next: { translate: ['100%', 0, 0] }。
▎提示词（追问：百分比的参照物 + 落地配置）你说 translate 用百分比，那这个百分比到底是相对幻灯片自己还是相对外层容器算的？ 我本地已经装了 swiper 11.0.3 源码，请直接在 swiper/modules/effect-creative.mjs 里找到给 slide 写 transform 的那段代码， 用源码回答我；然后按"上一张缩小左移带角度、下一张放大右移进场"给我最终配置。
AI 回答要点（源码佐证）：源码 effect-creative.mjs 中 getTranslateValue() 对字符串原样透传（所以 '-22%' 会原样进入 transform）， 最终 targetEl.style.transform = 'translate3d(...) rotateX(...) rotateY(...) rotateZ(...) scale(...)'， 而 targetEl 是幻灯片元素本身。因此百分比按 CSS 标准 transform 规则，相对该张幻灯片自身的边框盒解析。
✅ 验证结果：点「creative 电影墙」按钮 → 实例 params.effect 变为 'creative'， 圆点仍为 6 个、slide 仍为 6 张（重建后无重复、无循环副本残留），无 JS 报错； 实际观感：左侧上一张缩小并向左退走、同时带约 8 度倾角，右侧下一张从画面右外侧推进并放大，纵深明显。
🎤 答辩抽问二（用自己的话回答）：prev / next 的 transform 各控制什么？transform 里的百分号是相对谁的？改一个数值让卡片转 20 度试试？
prev / next 各管什么：prev 管的是当前这张左边、正在退场的那张； next 管的是右边那张、正在进场的那张。两者是"一退一进"，合起来才有纵深。
我的电影墙写法里，prev 用 translate: ['-22%', 0, -140]（向左推 22%、再往后推 140px） 配 scale: 0.78（缩到 0.78 倍）、rotate: [0, 0, -8]（Z 轴歪 8 度）、 opacity: 0.75（半隐），合起来就是"镜头往后拉，墙上的照片越退越小、还歪着"； next 用 translate: ['100%', 0, 0]（从右边 100% 处推入）配 scale: 1.12， 就是"镜头往前推，下一张照片迎面变大"。
百分号相对谁：相对这张幻灯片自己的宽/高，不是外层容器。所以 '-22%' 是"这张照片自身宽度的 22%"， 这也是为什么官方示例用 '100%' 能把下一张完全推到画面外——正好是它自己的一整个宽度。
转 20 度：把 rotate 的第三个值（Z 轴）改成 [0, 0, 20] 即可，rotate 数组依次是 X / Y / Z 轴， 第三个才是画面里"转个角度"的那个平面旋转。

⚠️ 我核对后发现并改掉的问题：AI 给的是 PNG、1.88 MB，而 swiper-imgs/ 里另外 5 张展品都是 JPG， 体量也不一致。我的处理：本机没有 PIL / ImageMagick，就用 Chrome 的 canvas 把 PNG 转成 JPG （canvas.toDataURL('image/jpeg', 0.88)，再用 --allow-file-access-from-files 解决 file:// 下 canvas 被污染无法导出的问题）， 体积从 1.88 MB 降到 272 KB，比例仍是 1536×864 = 16:9，画面右下角的「AI生成」水印我特意保留——它就是这张图由 AI 生成的现场凭证。
▎提示词 B（超纲能力：键盘控制）在 Swiper 轮播上再加一个课堂没讲过的能力，我选 keyboard 键盘控制。 请告诉我 keyboard 参数该怎么写、默认行为是什么、以及有没有什么坑（比如会不会影响我在输入框里打字）。
AI 回答要点：keyboard: { enabled: true } 即可开启，onlyInBrowser: true 表示只在真实浏览器窗口里生效、 不在 iframe / 某些编辑器环境里劫持方向键。我采纳了这一条并补上了 onlyInBrowser: true，避免在课堂编辑时误触翻页。

🎤 答辩四连问
① 这段代码什么意思？——keyboard: { enabled: true, onlyInBrowser: true } 是 Swiper 的键盘控制模块， 开启后用户按键盘方向键 ← → 就能切换上一张 / 下一张，不用鼠标拖；onlyInBrowser 把这个能力限制在真实浏览器里。
② AI 第一次给的哪里不对、你改了什么？——AI 第一次只给 keyboard: { enabled: true }， 漏了 onlyInBrowser。我读源码时发现 keyboard 模块默认会在绑定页面时监听 keydown， 在编辑器里敲方向键可能误翻页，于是补上了 onlyInBrowser: true。
③ 新参数的作用？——keyboard.enabled 开关键盘控制；keyboard.onlyInBrowser 限定只在浏览器生效；keyboard.pageUpPageDown 可额外启用 PageUp/PageDown 翻页。
④ 现场把 delay 改成指定值并解释预期变化？——改 autoplay.delay 的毫秒数即可， 它表示每张图停留多久再翻到下一张：改成 1000 就是 1 秒翻一张（节奏明显变快、更像广告 Banner）； 改成 8000 就是 8 秒一张（变慢、适合需要看清文字的展品说明）；delay 只影响停留时长， speed 才决定切换动画本身走多快，两者互不干扰。
